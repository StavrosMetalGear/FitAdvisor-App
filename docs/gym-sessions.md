# Gym Session increment — 0.5.0

The increment was implemented in the requested order: persisted session logging/recovery, optional rest timing, exercise/session history and benchmarks, then explicit completed Health Connect session linking. No commits or pushes were made.

Gym Session is available from Home and the navigation menu. Greek/English follows the existing language preference in Settings; the new cards and controls use the existing light/dark design. Session actions save before updating the displayed state. A failed save leaves the last saved state intact. Numeric set dialogs hide irrelevant fields, use the phone's decimal separator, and allow cancellation before saving. Incomplete dialog input is not a completed set and is not recovered.

Start a session, search the offline starter catalogue by English/Greek name, muscle group or equipment, then log completed sets. There are 20 starter variations, not every gym exercise. Custom variations are supported. Selector results are ordered by muscle group and name. Machine variations require a gym/machine identifier when first added; select that saved variation subsequently. Different machines or equipment conventions must use different variations.

All resistance is in kg, duration in seconds and distance in metres. Barbell load includes the bar. Paired dumbbell exercises record kg per dumbbell and simultaneous reps for the pair. Machine load is the displayed machine kg; assistance is explicitly separate from added resistance. Bodyweight sets do not record kg. Warm-ups and working sets are distinct. Undoing a set retains its values as pending; completing it again restores it. Editing preserves set order and completion state. Deleting a set and cancelling a session ask for confirmation. Cancelled sessions retain their saved sets and can be resumed from history.

Session timing uses accumulated active seconds plus a UTC running timestamp; pausing persists accumulated time, resuming saves a new timestamp. Time away/locked counts while running. Session and rest pause controls are independent. Display refresh is every two seconds; calculation does not depend on dispatcher ticks. Changing the device wall clock can affect running timers. A finished session writes its detailed payload and one manual workout atomically. Repeated finish saves replace that same ID. A gym plan launches a session; legacy planned sets become pending sets with their original external-load convention. Finishing replaces that plan's workout ID. Undo finish restores planned status, or removes the completed manual entry, and resumes the saved sets. Planned duration is replaced by actual duration; undo preserves that actual duration in the restored plan. To remove the final completed set of a finished session, undo the session finish first.

Rest is off by default. Preferences include automatic start after completing a set, default seconds, optional foreground sound/vibration, and hiding technique. Exercise rest overrides are stored with that session's exercise snapshot; blank uses the default. Rest supports start/reset, pause/resume, +30 seconds (up to two hours total), and skip. Expired rest stays at zero. There are no scheduled/background alerts and no notification permission request in this version. Android VIBRATE is a normal manifest permission; it is only used when vibration is enabled. Visual remaining time is the fallback, and reopening an expired timer may produce the enabled foreground cue. Foreground audio respects device behavior; physical audio/haptics acceptance remains pending.

Benchmarks use completed working sets only. Comparison requires the same exercise ID, equipment, resistance mode, units and weight convention. Heaviest load and maximum reps at each identical load are retained; lower assistance has its own benchmark. No estimated one-rep maximum is displayed. Working external-load volume is reps × load for conventional loaded-rep exercises only. Simultaneous paired dumbbells multiply per-hand kg by two. Warm-ups, pending sets, bodyweight, added-weight and assisted sets, duration and distance contribute no invented volume. Session volume is a logging summary, not a physiological workload measure or a cross-machine comparison. Each exercise shows previous sets and a dated trend from its five most recent completed sessions. The session list displays the 30 most recent sessions; all records remain stored and included in benchmark calculations. Per-load summaries display up to 20 loads.

Strength sets remain separate from Health Connect sensor data. Linking is an explicit choice between a finished manual session and an overlapping imported strength/weightlifting session. The selector and saved link show source package, start time and duration. A source import can be linked to only one gym session. Workouts retains provenance and excludes the linked import from duplicate completed totals, counting the manual session's duration once. Unlink restores its independent total. Repeat import preserves IDs/linking; an edited source that no longer overlaps or changes exercise kind is rejected atomically until the user unlinks it. The current Android import reads completed Exercise sessions, not live Mi Band data. Heart rate and calories are unavailable. No calorie estimate is made and food allowance never changes.

Database schema 5 adds gym_sessions, gym_exercises and gym_preferences without changing existing tables. Exercises and sets are retained inside each session's JSON snapshot; custom exercises and preferences have their own rows. Source-generated JSON supports Release trimming and reflection-disabled verification. Encrypted backup format 5 includes active/paused timers, session exercise snapshots, sets, custom exercises, preferences and explicit links. The authenticated FITADV01 envelope and existing encryption are unchanged. Backup formats 1–4 remain accepted with empty gym defaults. Restore validates references and atomically replaces all diary data. Appearance/theme/language preferences still remain device-local as before.

Technique is accessible from each exercise unless hidden in gym preferences. Written guidance remains offline, and opening/closing it preserves the saved active session. The exact bodyweight squat and floor push-up variations have concise Greek/English setup, movement, breathing, mistakes and safety guidance. Other variations, including custom exercises, explicitly say reviewed guidance is unavailable. Guidance is source-checked editorial content, not a clinical or trainer assessment. General cues encourage controlled movement, appropriate resistance and stopping with pain.

Automated verification runs use `verification/Gym/FitAdvisor.GymChecks.csproj` in Release with `JsonSerializerIsReflectionEnabledByDefault=false`. See the verification results below and the short phone checklist; do not infer physical-device or background-alert acceptance from emulator/core checks.

Phone checklist:

1. Export an encrypted backup, then update in place with the same certificate. Keep existing food, habits and workouts. Do not uninstall or clear storage.
2. Offline, log one loaded, one bodyweight and one assisted set. Check kg conventions and irrelevant fields. Edit, undo, re-complete and cancel a deletion.
3. Start rest, lock, reopen, pause/resume and restart the app. Completed sets must survive; running time advances and paused time stays fixed. Test optional sound/vibration on the actual phone, including silent/DND behavior. No locked-screen alert is expected.
4. Open technique and return, try Greek/English, dark/light and large fonts with TalkBack. Hide guidance. Finish/review, undo finish and finish again; there should be one workout total. Launch and finish a planned gym workout.
5. Export/restore a backup containing an interrupted session, custom exercise and preferences. With a real compatible completed Mi Band import, explicitly link/unlink and check source/time and single-entry totals. No heart rate/calorie or live-band data should be implied.
