# Food, gym and sensor sources — 0.6.0

Reviewed 2026-10-16. No physical-phone or Mi Fitness export test was performed.

## Food sources and network privacy

The embedded USDA SR Legacy April 2018 catalogue is unchanged: 7,793 original FDC identities. See [existing provenance](offline-food-catalogue.md). Historical meal snapshots are never refreshed from a catalogue.

Open Food Facts integration follows its [current API documentation](https://openfoodfacts.github.io/openfoodfacts-server/api/), [API conditions](https://support.openfoodfacts.org/help/en-gb/12-api-data-reuse/94-are-there-conditions-to-use-the-api), and [reuse terms](https://world.openfoodfacts.org/terms-of-use). Barcode lookup uses v3.6. Brand/name full-text lookup uses the documented legacy `/cgi/search.pl` endpoint; v2 structured search is not full-text search. Revisit this dependency when the dedicated search service is suitable.

Current limits are 10 searches/minute/IP and 15 product reads/minute/IP. FitAdvisor requires an explicit lookup button, serializes requests, and gates both endpoint types to one request per eight seconds. There are no network requests while typing, automatic retries, prefetches or bulk downloads. A 429/503 imposes at least a minute's cooldown; shared-IP quotas can still be reached. The gate lasts for the application process, not across restarts. Requests time out after 15 seconds. Local autocomplete is immediate and offline.

New Android INTERNET permission enables optional HTTPS lookup at `world.openfoodfacts.org`. Requests contain only the search/barcode, requested fields, search/pagination options and a `FitAdvisor/0.6.0` User-Agent with the public repository URL. The service also sees the IP and normal transport metadata. No meal dates, portions, diary IDs, profiles, health records, workouts or backups are sent. There are no analytics, cloud backups or remote crash reports. Camera scanning is deferred; no camera permission is declared. Barcode numbers can be typed/pasted.

OFF's database is ODbL 1.0; individual contents are DbCL 1.0. Product photos have separate CC BY-SA and potentially other rights; none are downloaded/bundled. Attribution travels with cached products and frozen meals and appears in the food privacy dialog. OFF cache entries have separate `off:` identities and explicit sources; the APK contains no redistributed OFF catalogue. USDA remains a separate embedded resource; local corrections use `custom` identities. Personal encrypted backups include selected source-tagged products. Publishing an extracted/adapted cache or combined database would require ODbL notices, attribution and applicable share-alike/source-offer compliance; do not distribute it as an unrestricted proprietary dataset. Complete OFF terms govern reuse. OFF asks API reusers to submit its usage form; no form/account submission or communication was made on the user's behalf. Arrange that and a maintainer contact before public-scale distribution.

The adapter reads normalized per-100 values or derives them from an explicitly sized g/ml serving. Conversion is 4.184 kJ/kcal. Package/serving evidence must establish grams versus millilitres; no density equivalence is assumed. Missing energy, ambiguous basis, source quality flags, implausible nutrients and materially inconsistent kcal/kJ prevent logging and offer local label correction. Unknown macros remain null. Prepared fields are not substituted for as-sold fields. Users must check the exact variant, barcode, package label and preparation. Greek supermarket coverage is incomplete.

One read-only smoke request to the official staging v3.6 API used its documentation's sample barcode `3274080005003`, with the documented public staging credentials and app User-Agent. The response identified Cristaline/isabelle, 1500 ml, with no nutriments. A retained test fixture verifies that this real response keeps ml and blocks logging of missing energy. It is OFF data under the terms above. This is not a successful Greek product-search or phone-network acceptance test.

## Offline technique photos

18 starter variations have three labeled steps: back/bodyweight squat, inclined sled leg press, leg extension, seated leg curl, conventional deadlift, medium-grip flat barbell bench, paired flat dumbbell bench, floor push-up, front wide-grip pulldown, seated close-neutral cable row, unweighted overhand pull-up, back-supported seated paired dumbbell press, standing paired lateral raise, simultaneous standing dumbbell curl, straight-bar overhand cable pushdown, forearm plank and treadmill walk.

Photos and reference instructions come from [Yuhonas / Free Exercise DB](https://github.com/yuhonas/free-exercise-db), credited upstream to Ollie Jennings' original dataset. Upstream declares the dataset public domain and supplies the Unlicense, preserved in [exercise-assets-LICENSE.md](exercise-assets-LICENSE.md). [The asset manifest](technique-assets-manifest.json) records upstream image paths and SHA-256 hashes. No AI-generated exercise imagery is used. Old illustrative SVGs remain in the repository but are no longer used as technique guides.

All paired photos were visually inspected for equipment/variation and concise original English/Greek cues were checked against source instructions. This was a source/visual consistency review, not a qualified trainer or clinical assessment. The upstream plank setup photo is an unrelated kneeling pose and is excluded from APK resources. Plank repeats its hold photo with distinct setup/hold/finish cues. Cyclic return frames reuse setup photos; treadmill uses side/rear walking views, with stop instructions in text. The cable-row cue discourages torso rocking. Photos are demonstrations, not individual assessments.

Weighted pull-up, machine-assisted pull-up and custom/machine-identified variations explicitly say guidance is unavailable. Exact identity/equipment/convention checks prevent substitution. A generic machine photo does not certify the user's exact model. Matching assets and review remain necessary for unsupported variations.

## Mi Fitness and Health Connect findings

[Google's Mi Fitness integration information](https://support.google.com/googlehealth/answer/14236613?hl=en-GB) lists exercise heart rate, energy and exercise summaries, while emphasizing upstream/device-dependent availability. It does not establish that energy is exported as active rather than total energy on this user's phone. [Xiaomi's integration instructions](https://www.mi.com/uk/support/faq/details/KA-517372/) describe third-party settings. Neither proves a successful export here.

[Android's supported types](https://developer.android.com/health-and-fitness/health-connect/data-types) and [workout guidance](https://developer.android.com/health-and-fitness/health-connect/experiences/workouts) support ExerciseSession, HeartRate and ActiveCaloriesBurned. Existing Exercise import and optional history access remain separate. After explicit linking, sensor switches start off and request only each enabled measurement's read permission. No startup/background sensor reads or Health Connect writes are added. No total-energy, route, location or body-measurement permission is added.

Enrichment uses the manual/imported time intersection and exact linked DataOrigin, followed by a second origin check. Other/Pixel sources are not merged. Saved data contains heart samples/timestamps, sample mean/min/max, first/last sample times and coverage explanations. Sample range does not imply continuous coverage. Only fully contained active-energy intervals are counted; boundary intervals are excluded, not prorated. Duplicate IDs are removed; competing overlapping intervals make energy unavailable. Native calories are converted to kcal. Missing is not zero. Enrichment neither adds workout totals nor increases food allowance. Incompatible changes to linked source times are rejected until explicit unlink/reimport. Subjective effort is separate and resets on repeat.

The reviewed Health Connect types contain no Xiaomi aerobic/anaerobic training-effect field. No supported Xiaomi score-export API was established by the official material. Xiaomi documents [personal-data export](https://www.mi.com/global/support/article/KA-11566/), but its schema/score contents were not inspected or integrated. No reverse engineering or substitute score is provided. Actual source packages, permissions, exported samples and coverage remain phone checks.
