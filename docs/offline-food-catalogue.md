## Health Connect findings

- `AndroidManifest.xml` retains only Health Connect `READ_EXERCISE` plus the generated signature-only internal receiver permission. Both the source and packaged APK exclude INTERNET. No write, routes, location, heart-rate, calorie, distance, steps, background or extended-history health permissions were added.
- Navigation: Home → **Health Connect Import → Open**, or Menu → **Workouts**, then scroll down to **Health Connect import**. The Home shortcut opened Workouts on the emulator but did not automatically scroll to the section; manual scrolling is currently necessary on that first navigation.
- `AndroidHealthSessionReader` uses the Android 14+ platform Health Connect manager. It validates dates within the last 30 days, requests Exercise read access only after Import, waits for the activity to resume, reads paginated exercise sessions while foregrounded, and returns all records before local writes. Invalid ranges, denied/revoked access, timeouts, repeated pages and excessive results are rejected. Android 13 and earlier retain manual logging but cannot use this reader.
- Session type, time/offset, duration, title, notes, source package, external ID and modification time are retained. Session-only import does not obtain distance, energy, routes or heart rate. Running and strength sessions receive local run/gym classifications; other source types remain other with the exact exercise type preserved.
- The UI asks for confirmation after reading sessions and before saving. Storage uses one transaction and a unique index on `(source, source_package, external_id)`. Repeated unchanged imports skip records; newer source versions update the existing local ID. Local deletion permits explicit reimport. Different source IDs are separate records even if they represent the same workout; content-based cross-app duplicate detection is not implemented.
- Emulator: navigation and Exercise-only permission prompt passed; denial left no workouts and displayed “Nothing was imported”; granting access read an empty store and displayed “No readable sessions”. Storage regression tests passed for duplicate imports, updates, provenance, atomicity and calorie-target isolation. **No successful Mi Fitness/Mi Band import is claimed.**

## Exact phone test

Use Android 14 or later. Update in place using the same signing identity; do not uninstall or clear app storage. The steps below use English labels; your Mi Fitness version/region can expose different integration options.

1. Open **Mi Fitness → Device**, sync the band, and verify it is connected. Record and finish a short identifiable workout on the band today. Sync again and open that workout in Mi Fitness; note its date, start time, type and duration.
2. Open **Mi Fitness → Profile → Third-party data → Health Connect** and enable/connect it if offered. In its Health Connect permission screen, enable **writing Exercise** (called Exercise sessions in some versions). If Health Connect or Exercise writing is absent, stop at this point: a working upstream path has not been established. Do not substitute steps or calorie totals as evidence of a workout session.
3. Open Android **Settings**, search for **Health Connect**, and open it. Under **App permissions → Mi Fitness**, check Exercise write access. Under **Data and access → Activity → Exercise**, locate the newly synced session and verify its source is Mi Fitness and its time/type/duration match. If your Health Connect screen offers Browse data instead, open Activity → Exercise there. If no session exists, FitAdvisor has nothing to import; record the Mi Fitness version, band model, region and permission state for troubleshooting.
4. Open **FitAdvisor → Menu → Workouts**. Scroll below the manual form/list to **Health Connect import**. Set **From** and **Through** to the workout's local date (within the last 30 days). Tap **Import**, grant **Exercise read** access, keep FitAdvisor foregrounded, then approve **Import exercise sessions? → Import** if sessions are found.
5. Verify the imported row's source, date, type and duration against Health Connect/Mi Fitness. Repeat Import for the same dates: unchanged source sessions must add zero copies. A successful new session import from this phone is the evidence needed to claim the complete band → Mi Fitness → Health Connect → FitAdvisor path works.
6. Force-stop and reopen FitAdvisor; the imported workout must remain. Verify the calorie target/meal allowance did not change. Optional denial test: revoke FitAdvisor's Exercise read access in Health Connect, retry and decline access; existing local workouts must remain untouched.

Google documents Mi Fitness sharing via Health Connect and cautions that availability depends on what the upstream app shares: [Google's Mi Fitness integration information](https://support.google.com/googlehealth/answer/14236613?hl=en-GB). Xiaomi documents the Profile/third-party integration entry point: [Xiaomi third-party data support](https://www.mi.com/uk/support/faq/details/KA-517372/). These documents do not establish that this user's band or phone has successfully synchronized.

## Catalogue provenance and scope

- Source: [USDA FoodData Central downloadable data](https://fdc.nal.usda.gov/download-datasets/), **SR Legacy April 2018 JSON**, [official ZIP](https://fdc.nal.usda.gov/fdc-datasets/FoodData_Central_sr_legacy_food_json_2018-04.zip).
- The preserved `artifacts/usda-sr-legacy-2018-04.zip` is a truncated 2,342,638-byte ZIP (SHA-256 `F8CAD2A6FD2D3293344617DF11A5585845A1BDFE2242B541CD8238993664F297`). Its header declares a 13,456,064-byte compressed JSON member; its central directory is missing. It was not overwritten. A separate `artifacts/usda-sr-legacy-2018-04-complete.zip` was downloaded from USDA. The original is byte-for-byte an exact prefix of the complete archive.
- Complete archive SHA-256: `0FE8AE486A2C8EB42CB96413F058DEB51863A46C8FB8EEB4B1FB45006DD338EF`. JSON member: `FoodData_Central_sr_legacy_food_json_2018-04.json`, 210,758,826 bytes.
- **7,793 food records**, each with its original FDC ID and full English description. **46 curated Greek food-name alias groups cover 2,668 records** (34.2%). Aliases are common-food search aids, not official USDA translations or nutrition sources. Raw/uncooked and cooked entries also support Greek preparation search terms. Accents, case and Greek final sigma are normalized. Search returns up to 60 matches and asks the user to narrow broad queries.
- Reproducible builder: `tools/CatalogueBuilder`. Bundled resource: `FitAdvisor.Core/food-catalogue.tsv`. It copies reported nutrient numbers 208 (kcal), 203 (protein g), 205 (carbohydrate g), 204 (fat g), per 100 g. No values are inferred from energy factors or missing nutrients. This particular archive reports kcal for every record; absent macros remain nullable, and code rejects saving a catalogue food without reported kcal.
- Use **Food Diary → Search offline food catalogue → enter name → Search offline → Select this food → enter grams → Preview nutrition → Save previewed meal**. The source description remains visible so preparation, cuts, added ingredients and processing are distinguishable. Raw/uncooked and cooked labels direct users to weigh that preparation; unspecified preparation is explicitly identified. Estimates apply to the edible portion, not bone, peel or an assumed recipe.
- Meals save scaled totals plus source/release, FDC ID, description, grams and the original per-100-g nutrients. Display and dashboard totals read saved values rather than resolving a live catalogue reference. Editing a catalogue entry recalculates from its saved snapshot. Manual nutrition entry remains available for unmatched foods.
- Schema migration 3 → 4 adds a nullable `nutrition_snapshot` column without rewriting existing meals. Encrypted backup format 3 includes snapshots and all existing habits/workouts/history; formats 1 and 2 remain readable. Older app versions cannot read new format-3 backups; use 0.4.0 for those restores. AES-GCM/PBKDF2 encryption and atomic validated restore are unchanged.
